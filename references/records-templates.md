# 记录模板（records-templates）

建项目、建变更、建数据抓取记录前先读本文件。模板以「一般项目：`<项目根>/records/`」为准；Vault 里只装记录的项目目录本身就是记录根（`<Vault 根>\软件开发\<项目名>\`），内容一致、只是位置不同。

## 0. 记录位置与 Vault 根

- 记录位置：一般项目 `<项目根>/records/`；Vault 内的项目目录直接当记录根；可由项目 `AGENTS.md` 或用户当场指定覆盖；
- **是否纳入版本控制（提交、推送、公开）由用户与 Agent 协商，本 skill 不规定**；
- **Vault 根只从技能目录下的 `config.json` 读取**（字段 `vaultRoot`，与 `SKILL.md` 同级，不入库）；读不到就**不猜路径**，直接告知用户缺配置，并给修复办法：复制技能目录里的 `config.example.json` 为 `config.json`，填上自己的 Vault 路径。

## 状态与字段规范

- 变更状态只有四种：`待开始`、`进行中`、`受阻`、`已完成`；
- `负责人` 填当前 Agent 身份（写你自己认得出来的名字，如 `Kimi Code`、`Codex`）；
- `最后更新` 格式 `YYYY-MM-DD HH:mm`；
- 标题统一用 `## 验证`（历史上 `验证` / `验收` 混用，自本版起统一为 `验证`；旧文件按各自原样保留，不回头改）；
- 变更目录名 `YYYY-MM-DD 主题`，日期取变更开始日，主题不含 `\ / : * ? " < > |`；
- 变更目录下**只允许五种文件名**：`变更.md`、`spec.md`、`任务.md`、`产出.md`、`handoff.md`；
- 不在聊天里留状态，不在记录里写密钥或账号。

## 1. `SPEC.md`（系统总规格）

粗粒度、可通读；不抄能力规格条文。有 `openspec/` 之类规格体系时，「详细规格」列填链接。

```markdown
---
项目: "<项目名>"
版本: 1
状态: 待确认
最后更新: YYYY-MM-DD HH:mm
---

# <项目名> SPEC

## 系统是什么

（一段话：这个系统做什么、给谁用、为什么存在）

## 由哪些能力组成

| 能力 | 一句话现状 | 详细规格 |
| --- | --- | --- |
| 例：会话管理 | 支持多会话切换与恢复 | `openspec/specs/session/spec.md` 或 `（无）` |

## 边界与非目标

## 当前阶段与范围

- 范围：
- 验收标准：
- 非目标：
- 约束：

## 范围变更记录

| 日期 | 变更 | 原因 | 确认人 |
| --- | --- | --- | --- |
```

（没有规格体系时，行为变化写在 `变更/<日期 主题>/spec.md`，收尾时并入本文件对应小节。）

## 3. 变更（多文件形态）

命中任一触发线时使用：子项 ≥ 3；需跨会话或跨 Agent 交接；范围或验收标准要写进 `SPEC.md`；要留完整验证证据。

### 3.1 `spec.md`（本次变化正文）

```markdown
---
状态: 待开始
负责人: 未认领
最后更新: YYYY-MM-DD HH:mm
---

# <变更主题>

## 本次要改成什么

## 验收标准

## 触及的总规格小节

（有规格体系时改为：指向 `openspec/changes/<change>/` 的链接 + 本次范围与验收标准，不写条文）
```

### 3.2 `任务.md`（子项与进度）

```markdown
---
状态: 待开始
负责人: 未认领
最后更新: YYYY-MM-DD HH:mm
---

# <变更主题> 任务

## 子项

- [ ] 

## 进度记录

| 时间 | Agent | 进度 | 证据 |
| --- | --- | --- | --- |

## 阻塞与风险
```

### 3.3 `产出.md`（交付物，可选）

本次变更的交付物：盘点清单、方案、调研结论、设计草案……**没有交付物就不建这个文件**。

- **不放 frontmatter**（状态与负责人跟着 `任务.md`）；
- 开头写清「这是什么、来源是什么」，正文用带来源的表或分节；
- 交付物会变长没关系，它本来就是产物；但**别把过程记录混进来**（进度、阻塞写 `任务.md`）。

```markdown
# <交付物名称>

来源：<读了哪些文件 / 跑了哪些命令>。

## <正文：清单 / 方案 / 结论>
```

### 3.4 `handoff.md`（收尾交接）

```markdown
# <变更主题> handoff

## 已完成
## 未完成
## 下一步（确切动作）
## 验证证据

（命令与输出，或说明为何无法验证）

## 风险
## 范围偏离

（与 SPEC 的偏离；无则写「无」）
```

## 5. 每日数据抓取

路径 `<Vault 根>\每日数据抓取\YYYY-MM-DD\`：`数据.md`（抓取结果）、`来源.md`（每个来源或本地输入）、`运行日志.md`（命令、时间、错误、结果）。

## 6. 迁到新记录位置时的检查表

1. 目标位置：一般项目 `<项目根>/records/`；Vault 内项目直接放项目目录；有 `AGENTS.md` 或用户指定的以声明为准；
2. 迁移时复制原位置的 `SPEC.md`、`任务计划.md`、在途变更；历史 `任务/`、`handoff/`、`决策/`、`日志/` 不搬；
3. 旧位置原文件加「已迁移，只读」标注，并在其中写明新位置；
4. 是否提交进版本控制：由用户与 Agent 协商（本 skill 不规定）；
5. 验证：新位置只显示新增文件（若纳入版本控制用 `git status`）；旧位置内容未变（`git diff --stat` 只有新增行）。
