# Project OS v1.3 项目删除与任务多视图设计

## 目标

在 v1.2.0 黑绿玻璃控制台的视觉与交互基础上补齐两组能力：

1. 项目负责人可以安全地永久删除项目及其业务子数据。
2. 任务控制台在现有扇面视图之外增加看板和时间线视图，并让三种视图共享筛选、选择和详情状态。

本次版本号为 `1.3.0`。实现应延续当前组件、样式令牌和数据访问边界，不整体替换全局样式，也不引入与目标无关的重构。

## 已确认的产品决策

- 项目删除为永久删除，不设置回收站或软删除阶段。
- 默认项目不可删除。
- 只有系统 Owner 或项目负责人可以删除项目。
- 删除前必须输入完整项目名称确认。
- 项目业务子数据随项目级联删除，审计活动保留。
- 任务控制台默认仍显示扇面视图。
- 任务控制台提供 `扇面 / 看板 / 时间线` 三种视图。
- 看板支持拖拽更新任务状态，并提供可键盘操作的替代方式。
- 右侧任务详情在三种视图中持续存在并展示真实派生信息。

## 范围

### 包含

- 项目详情页的永久删除入口、确认对话框、权限反馈和删除后导航。
- contracts、core service、server route、数据库操作和前端 repository/query mutation 的删除链路。
- 任务控制台三视图切换、共享查询状态、看板状态变更和时间线展示。
- 对应的单元测试、组件测试、接口测试和真实运行时端到端测试。
- `1.3.0` 版本、变更日志、PR、tag、GitHub Release 和本地 `main` 同步。

### 不包含

- 项目回收站、恢复、批量删除或定时清理。
- 看板列自定义、泳道、自定义工作流或跨项目批量移动。
- 创建新的 AI 服务或展示无法由现有数据推导的 AI 结论。
- 对全站视觉体系进行第二次重写。

## 任务控制台

### 页面结构

保留现有任务页的指标区、搜索筛选、任务工作区和右侧上下文面板。工作区顶部增加三段式视图切换：

- **扇面**：默认视图，保留紧凑任务列表和关键任务玻璃扇面。
- **看板**：按任务状态分为未开始、进行中、已完成、已逾期四列。
- **时间线**：按开始和截止日期绘制横向任务条，标记今天并支持点击任务。

右侧详情面板不随视图切换销毁。桌面端固定显示；紧凑布局中改为可打开的抽屉。看板和时间线允许自身水平滚动，不能推动整个页面产生横向溢出。

### 共享状态

`TaskPage` 继续作为任务工作区编排层，并维护以下单一来源状态：

- URL 中的搜索、状态、负责人、优先级和排序条件。
- URL 中的 `selected` 任务 ID。
- 当前视图，可使用 `view=fan|board|timeline` 表达；缺省或非法值回退为 `fan`。
- 由筛选结果推导的指标、可见任务和当前选中任务。

三种视图接收同一份过滤后的任务集合、`selectedTaskId` 和 `onSelect`。切换视图时，筛选条件与选中任务保持不变；若选中任务不再属于筛选结果，则选择当前视图中的第一个可见任务，没有任务时清空详情。

### 看板状态变更

任务卡可以在四列之间拖动。放置后通过现有任务更新边界提交状态和进度：

- `not_started` 对应进度 `0`。
- `done` 对应进度 `100`。
- `in_progress` 和 `overdue` 的进度限制在 `1–99`；原进度不在范围内时使用最接近的边界值。

前端允许乐观移动，但必须保留上一个任务快照。请求失败时恢复原列、原进度和原选中状态，并在工作区显示可理解的错误消息。请求成功后刷新任务相关查询，确保指标、列表、详情、项目摘要和甘特数据一致。

拖拽不是唯一入口。每张任务卡都要暴露键盘可聚焦的“移动到”操作，让用户从菜单中选择目标状态。卡片本身的点击仅选择任务，不触发状态变更。

### 时间线

时间线复用现有任务日期语义和玻璃视觉令牌，不复制甘特页的完整编辑能力。它只负责：

- 展示任务名称、起止区间、状态与选中态。
- 标记今天的垂直基准线。
- 点击或键盘激活任务后更新共享 `selected` 状态。
- 对缺少开始日期或截止日期的数据使用现有日期推导规则；两者均缺失时不绘制任务条，并在无日期分组中给出计数。

### 智能详情

详情面板展示任务编号、标题、项目、负责人、状态、优先级、日期、进度和标签。建议区域只能展示可由当前数据确定性推导的提示，例如：

- 已逾期且未完成。
- 临近截止日期但进度偏低。
- 缺少负责人或日期。
- 存在前置任务阻塞。

不得显示虚构的文档数量、模型判断或不存在的历史统计。

## 项目永久删除

### 入口与确认

删除入口位于项目详情页头部的“更多操作”危险区域。无权限用户不显示可执行入口；默认项目显示不可删除的解释，不提供绕过方式。

确认对话框包含：

- 项目名称和永久删除说明。
- 将被级联删除的数据类型提示。
- 要求用户输入完整项目名称的文本框。
- 默认禁用的“永久删除”按钮，仅在名称完全匹配且请求未提交时启用。

关闭对话框不改变数据。提交期间禁止重复提交，且不得提前离开项目页。

### 接口与并发控制

使用 `DELETE /api/v1/projects/:projectId`，请求携带调用方看到的项目版本号。contracts 层定义请求、成功结果和稳定错误码。至少覆盖：

- `PROJECT_NOT_FOUND`
- `PROJECT_DELETE_FORBIDDEN`
- `DEFAULT_PROJECT_PROTECTED`
- `PROJECT_VERSION_CONFLICT`
- `PROJECT_DELETE_FAILED`

服务器必须从可信调用上下文判断操作者身份，不能接受前端传入的任意操作者 ID 作为授权依据。删除前重新读取项目、校验版本、默认项目和权限。

### 事务与审计

删除在单一数据库事务内完成。任务、需求、缺陷、里程碑、项目成员关系以及其他以项目为生命周期边界的业务记录随项目删除；任一步骤失败则整体回滚。

审计活动不随项目删除。删除前写入 `project.delete` 活动，至少保留：

- 操作者 ID。
- 原项目 ID 和名称。
- 删除时间。
- 删除结果以及必要的关联数量摘要。

若活动表存在项目外键，删除后该外键设为 `NULL`，同时依靠活动负载中的原项目 ID 和名称保留追溯能力。审计记录写入与业务删除处于同一事务，避免产生“已记录删除但实际未删除”的矛盾状态。

### 前端成功与失败行为

删除成功后：

1. 清除项目、任务、需求、缺陷、仪表盘和活动相关查询缓存。
2. 从客户端当前选择中移除已删除项目。
3. 导航至项目列表，并选择仍然有效的工作区或默认项目。
4. 显示一次成功通知。

授权失败、默认项目保护、版本冲突、网络错误和服务器回滚都保留当前页面和已输入的项目名称。版本冲突提示用户刷新后重新确认；其他错误提供原因和重试入口。

## 代码边界

- `packages/contracts`：删除请求、响应、错误码和序列化约束。
- `packages/core/project-service.ts`：删除规则、权限、默认项目保护和审计编排。
- `apps/server/src/routes/projects.ts`：HTTP 输入校验、身份上下文、错误映射和响应。
- 数据库迁移/存储层：级联策略、审计外键行为和事务实现。
- `web/src/data`：repository 删除方法、任务状态更新复用、query mutation 和缓存失效。
- `web/src/features/projects`：删除入口与确认对话框。
- `web/src/features/tasks`：共享视图编排、看板和时间线组件。

应优先复用 `Button`、`GlassPanel`、`SegmentedControl`、现有任务更新 mutation、日期推导和响应式样式。旧 stash 只作为功能参考，不能整体应用；旧全局 CSS 与 `.kimi-code/mcp.json` 等本地配置不进入版本历史。

## 可访问性与响应式

- 所有视图切换、卡片、菜单和确认控件均可通过键盘访问，并具有可见焦点。
- 视图切换使用正确的选中语义；任务选择与状态移动使用不同的无障碍名称。
- 拖拽结果和失败回滚通过可感知的状态消息宣布。
- 删除对话框具备标题、描述、焦点圈定、Escape 关闭和关闭后的焦点恢复。
- 危险操作不能只依赖红色表达含义。
- 尊重 `prefers-reduced-motion`，减少卡片移动和玻璃过渡动画。
- 紧凑布局下详情为抽屉，看板和时间线只在自身容器内横向滚动。

## 测试策略

### 单元与服务测试

- 默认项目保护、Owner/负责人权限和无权限拒绝。
- 项目版本匹配与冲突。
- 级联删除范围、事务回滚和审计保留。
- 任务状态与进度归一化规则。
- 时间线日期推导和无日期任务处理。

### 接口与 repository 测试

- 删除接口的成功响应和稳定错误映射。
- repository 请求格式、错误解析和缓存失效。
- 任务状态更新成功、失败回滚和查询同步。

### 组件与端到端测试

- 三视图切换保持筛选和选中任务。
- 看板拖拽以及键盘“移动到”操作。
- 失败时卡片、指标和详情恢复。
- 项目删除确认名称、重复提交保护、成功导航和版本冲突提示。
- 默认项目与无权限用户不能执行删除。
- 桌面和紧凑布局无页面级横向溢出，详情抽屉、焦点和减少动效行为正确。
- 使用真实 server/runtime 验证创建项目、添加关联记录、删除项目、关联数据消失且审计记录保留的完整旅程。

## 发布流程

1. 在独立的 `codex/` 功能分支和 worktree 中实现，保持本地 `main` 可恢复。
2. 执行类型检查、单元测试、接口测试、前端构建和关键 Playwright 旅程。
3. 更新 `package.json`/lockfile 中相关版本和 `CHANGELOG.md` 为 `1.3.0`。
4. 推送功能分支并创建 PR，待验证通过后合并至远端 `main`。
5. 在合并提交创建并推送 `v1.3.0` tag，发布 GitHub Release。
6. 将本地 `main` 快进同步到远端 `main`，确认干净且指向 `v1.3.0`。
7. 原安全 stash 保留到发布完成；只有在确认其中无未迁移价值后才单独决定是否清理。

## 验收标准

- 项目详情页可由授权用户完成带名称确认的永久删除。
- 默认项目、无权限操作者和过期版本均无法删除项目。
- 删除是原子的，业务子数据消失，审计记录仍可追溯原项目。
- 任务页提供扇面、看板和时间线三种可用视图，默认仍为扇面。
- 三种视图共享筛选、搜索、选中任务和右侧详情。
- 看板拖拽会持久化状态和规范化进度，失败会完整回滚；键盘用户可完成同等操作。
- 时间线正确呈现日期、今天线、选中态和无日期任务信息。
- 右侧建议只基于真实数据推导。
- 关键测试、真实运行时旅程、响应式和可访问性检查通过。
- GitHub 上存在合并后的 `v1.3.0` tag 与 Release，本地 `main` 同步且无意外本地配置提交。
