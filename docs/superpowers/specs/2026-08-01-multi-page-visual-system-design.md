# Project OS 多页面视觉系统与可点击原型设计

## 目标

在已通过评审的任务控制台视觉方向上，制作一个离线、单文件、可点击切换的多页面 HTML 原型，用于验证 Project OS 全部主要页面是否能够保持统一的高级感，同时适合长时间办公使用。

原型覆盖仪表盘、项目列表、项目详情、负责人、任务、甘特图、需求、缺陷和设置九个页面。它是视觉与交互方向验证稿，不连接真实后端，不替换现有 React 页面，也不修改 `web/src`。

## 统一策略

采用“统一母版 + 页面签名区”策略：约 70% 的结构和组件共用，约 30% 根据业务目的变化。

### 固定母版

- 左侧 220px 导航统一使用 Project OS 品牌、分组导航、当前工作区和本地负责人卡片。
- 顶部统一使用页面标题、简短说明、搜索或筛选、通知入口和一个主操作。
- 内容统一按“概览区、核心工作区、上下文详情区”组织；没有详情需求的页面不强制显示右栏。
- 所有页面共用同一套近黑背景、烟灰玻璃、银色高光边缘、荧光绿焦点、字体、圆角、阴影、间距与状态色。
- 每个页面只能有一个强视觉焦点，其余区域保持低对比和克制。

### 页面母版

1. 概览型：仪表盘、项目列表、负责人。
2. 执行型：项目详情、任务、甘特图、需求、缺陷。
3. 配置型：设置。

## 视觉系统

### 色彩与材质

- 背景使用近黑色，并叠加低对比网格和局部环境光。
- 主面板使用烟灰色半透明玻璃、细银色边框、顶部内高光与深色阴影。
- 荧光绿只用于当前页面、选中对象、进行中状态、关键进度和主操作边缘光。
- 红色只表示逾期、严重缺陷和高风险；琥珀色表示中等优先级或需要关注。
- 主按钮使用深色玻璃与绿色边缘光，不使用大面积纯绿色填充。

### 排版与密度

- 使用系统中文无衬线字体，不依赖外部字体。
- 页面标题、指标数字和任务编号维持一致字号层级。
- 普通正文不低于 12px；交互元数据不低于 10px，并满足可读对比度。
- 页面内容以 1440×900 为主要画布，首屏应展示页面的核心决策信息。

### 动效规则

- 3D、连续发光和视差属于特殊能力，只允许出现在页面签名区。
- 普通面板只使用轻微悬浮、边缘高光和短时状态变化。
- 系统启用减少动效时，取消 3D 变换、漂移和连续动画。

## 页面设计

### 仪表盘

签名区为项目健康度轨道图。上方展示项目总数、进行中、待处理风险和活跃协作者；主体包含健康度趋势、风险队列、Agent 在线状态、最近交付物和活动流。点击风险或协作者更新右侧摘要。

### 项目列表

签名区为玻璃项目矩阵。卡片显示项目状态、负责人、进度、风险和目标日期；选择项目后显示项目摘要、关键阶段和下一步操作。筛选支持全部、正常、需关注和高风险。

### 项目详情

签名区为阶段里程碑轨道。主体展示项目简报、阶段进度、当前任务、交付物和最新接力记录；上下文区展示负责人、风险、会话和交接状态。

### 负责人

签名区为人类与 Agent 协作网络。节点显示在线状态、工作负载、技能和当前项目；选择节点后显示负责事项、协作对象和近期活动。网络图保持克制，不使用持续旋转或粒子动画。

### 任务

沿用已通过评审的任务控制台：四个指标、可滚动任务清单、3D 玻璃任务卡、智能详情和交付时间线。该页是整个视觉系统的基准页。

### 甘特图

签名区为深色时间轴。进行中任务使用绿色条，逾期任务使用红色标记，完成任务使用银灰色；包含今天线、依赖关系、缩放范围和任务详情。时间轴本身承担视觉焦点，不叠加 3D 卡片。

### 需求

签名区为需求生命周期管线：收集、评审、已批准、开发中、已交付。需求卡展示优先级、负责人和任务/缺陷追踪关系；选择需求后显示验收标准、关联任务与变更风险。

### 缺陷

签名区为风险分级与影响矩阵。缺陷队列按严重度和状态排列，红色严格用于阻塞或严重缺陷；选择缺陷后显示复现步骤、影响范围、负责人和关联版本。

### 设置

使用更克制的配置型母版。左侧为外观、数据、MCP 和 Skills 分组，右侧使用双栏玻璃表单和状态说明；不使用 3D、强发光或装饰性数据图。

## 可点击原型架构

交付文件为 `docs/prototypes/project-os-multipage-preview.html`。

- 左侧导航通过 URL hash 在九个页面之间切换，不刷新页面，并支持浏览器前进与后退。
- 页面数据、样式和脚本全部内嵌，不调用 API、不使用本地存储、不加载外部资源。
- 每个页面提供少量代表性交互：筛选、选中对象、范围切换、上下文详情和操作反馈。
- 任务页复用当前已验证的视觉与核心交互，但允许为多页面原型抽取共享结构，避免九页重复维护。
- 页面切换后更新活动导航、页面标题和主要内容，并把焦点移至新页面标题。
- 不可用操作提供原型反馈，不伪造持久化成功。

## 组件规则

- `AppShell`：品牌、导航、工作区卡片和全局背景。
- `PageHeader`：标题、说明、搜索、通知和主操作。
- `MetricCard`：指标、趋势和小型图形，状态色由语义决定。
- `GlassPanel`：普通、抬升和危险三种表面层级。
- `SegmentedControl`：范围和状态筛选，单一绿色活动态。
- `StatusBadge`：进行中、完成、关注、逾期和严重缺陷。
- `ContextPanel`：选中对象的事实、标签、建议与操作。
- `Toast`：短时原型反馈，使用礼貌的无障碍播报。
- 页面签名组件独立存在，不允许普通卡片直接复制其 3D 或强光样式。

## 响应式与无障碍

- 1440px 使用完整导航、主体和上下文区。
- 中等宽度缩减装饰性内容，并把上下文区移到主区下方。
- 小屏使用可横向滚动的局部可视化，不允许页面级横向溢出。
- 所有导航、筛选、卡片和主操作支持键盘；页面包含跳过导航入口和可见焦点。
- 状态不只依赖颜色表达；高风险、逾期和完成均有文字或图标标识。
- 尊重 `prefers-reduced-motion`。

## 一致性质量护栏

- 同一语义必须使用同一组件、状态色、圆角、间距和交互反馈。
- 每页最多一个高强度视觉焦点，绿色发光面积保持克制。
- 页面标题、指标区和上下文区在九页中保持相同基线。
- 设置页和高频表格页优先可读性，不为追求视觉效果牺牲信息扫描效率。
- 视觉验收至少覆盖 1440、1280、600 和 390px，并检查减少动效状态。
- 原型最终需要通过无外部请求、无控制台错误、无页面级横向溢出和关键键盘路径验证。

## 验收标准

- 一个 HTML 文件可离线打开，并可在九个页面间点击切换。
- 九页明显属于同一产品，但每页拥有与业务相符的签名区。
- 任务页视觉语言与现有基准原型一致。
- 所有页面共用相同母版、视觉令牌和基础组件。
- 1440×900 下每页核心信息在首屏可见，没有文字遮挡或页面级横向溢出。
- 页面切换、筛选、选中态和操作反馈均可使用键盘完成。
- 不修改现有 React 前端，不连接后端，不写入持久数据。
